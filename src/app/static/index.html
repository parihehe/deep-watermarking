01

Embed

The Phase 6 DWT-SVD embedder writes your message's registry ID into the LL singular values at α 0.02. Payload evidence — embedded bits, recovered bits, BER, PSNR/SSIM — is returned from one call.

02

Distribute

Hand out the watermarked file. No key, no sidecar, no original — the watermark is self-contained in the image spectrum and everything needed to verify it is registered locally.

03

Verify

Upload the image here. A blind decoder reconstructs the ID bits, the app recovers confidence and also reports the confidence of the vote, then looks the ID up in the message registry for the ownership text.

01 · Blade the source

Embed a watermark

Choose an image and its watermark text. The text is registered to a 4-bit ID and that ID is repeated 15× across the 64-bit payload the embedder writes into the LL subband. The result panel shows the registry entry, quality, reference-decoder recovery, and a reference payload to reuse in Verify.

Input

Registered locally as a 4-bit ID repeated 15× inside a 64-bit payload (gear: the exact repetition & kind are echoed into the Verify screen automatically).

Other payload sources

The final model embeds at a fixed α = 0.020, Haar / LL. For non-message payloads the blind decoder is available up to 128 bits.

02 · Read the blade

Verify a watermark

The watermarked image is the only input. The blind decoder reconstructs the payload, reports the confidence of that reconstruction, and looks the recovered ID up in the local message registry. No original image, key, or embedding metadata is required.

Watermarked image

Payload format (usually pre-filled automatically)

Registry-ID payloads from the Embed step carry bit_length 64, repetition 15, kind registry_id automatically. Leave the reference fields blank for a pure blind check — BER has no meaning without the embedded reference bits.
